# v2.5 — Vì sao "Rất cao" không lên, nút Phối nhạc, và viên badge chữ đen nền xanh

Tài liệu này ghi lại đúng những gì **log bắt gói 276 request** (nick có Premium thật) chỉ ra,
những gì v2.5 sửa, và những gì **không** sửa được bằng proxy.

---

## 1. Bằng chứng: chính module cũ đang tự bóp chất lượng

Log 2026-11-24 15:14:24 → 15:16:19, 276 request, policy ghi như sau:

| Policy | Số lần |
|---|---|
| `DIRECT` (host spotify) | 234 |
| `REJECT` | 15 |

15 lần REJECT đó **không phải quảng cáo**, mà là:

```
URL-REGEX,^https?://[^/]*spotify\.com/(?:ads/v3|ad-logic|net-fortune|sponsoredplaylist|premium-marketing),REJECT
```

và 15/15 URL bị chặn đều là:

```
/net-fortune/v2/fortune?bandwidth=7250555&request_type=interactive&...
/net-fortune/v2/fortune?request_type=interactive&content_type=music
```

`net-fortune` **không phải** service quảng cáo. Nó là service **chọn file nhạc**: client khai
"tao có ~7 Mbps", server trả danh sách file kèm bitrate/format cho bài sắp phát.
Chặn nó = app không bao giờ nhận được bản 320 → rơi về file mặc định 96/160 → dòng
**"Rất cao"** trong trang Chất lượng nội dung không bao giờ tick được, dù patch có đúng.

Đây là lỗi do mình gây ra từ bản đầu (chặn cả cụm endpoint cho nhanh), không phải do Spotify
siết. v2.5 bỏ đúng một mục đó, giữ nguyên phần chặn quảng cáo thật.

Các con số còn lại trong cùng log:

| Endpoint | Số lần | Ý nghĩa |
|---|---|---|
| `/storage-resolve/v2/files/audio/interactive/2/<id>` | 25 | cấp âm thanh nằm **trong đường dẫn**, tất cả đều cấp 2 |
| `/net-fortune/v2/fortune?bandwidth=…` | 15 | chọn file theo băng thông (bị chặn) |
| `/connect/v2/devices/<id>/jam_status` | 3 | cờ Jam (nút Phối nhạc) |
| `/device-capabilities/v1/capabilities` | 2 | danh sách chất lượng máy được phép chọn |
| `playback-settings` (gRPC) | 2 | cài đặt phát |
| `clientrestrictions GetRestrictedIntegrations` | 1 | danh sách tính năng bị khoá |
| `pam-*` | 0 | lần này app không gọi (badge đọc từ cache) |

## 2. v2.5 sửa gì

### 2.1 Bỏ REJECT `net-fortune` (quan trọng nhất)

`spotify-vn-premium.module`:

```
# v2.5
URL-REGEX,^https?://[^/]*spotify\.com/(?:ads/v3|ad-logic|sponsoredplaylist|premium-marketing),REJECT
```

`premium-marketing` vẫn chặn (banner bán Premium), `net-fortune` được thả.
Test có case riêng khẳng định module **không còn** chặn `net-fortune`.

### 2.2 Ép cấp âm thanh trong URL — `scripts/spotify-audio-level.js`

Cấp âm thanh không nằm trong body, nó nằm trong đường dẫn nên mọi hàm sửa response
(`patchJson`, `patchProto`, `patchJsonAll`…) **không bao giờ với tới**. Phải sửa ở bước request:

```
/storage-resolve/v2/files/audio/interactive/<cấp>/<file_id>?product=0
                                              ↑ 0 hoặc 1 → 2
```

- Chỉ đúng một hình dạng URL, không đoán mò.
- **Không đụng `?product=0`**: log nick Premium thật cũng gửi `product=0`, đổi là ăn 403.
- Tắt hẳn: `$argument {"audio_level":"keep"}`. Ép cấp 1 nếu bài nào không có bản cấp 2:
  `{"audio_level":1}`.

### 2.3 `net-fortune`: nâng bitrate trong danh sách file trả về

- JSON: `bitrate / max_bitrate / bitrate_bps` giá trị `96` / `160` → `320` (và `96000/160000 → 320000`).
- protobuf: chuỗi `OGG_VORBIS_96` / `OGG_VORBIS_160` → `OGG_VORBIS_320`, varint `96000/160000 → 320000`;
  varint khác (ví dụ `44100`, sample rate) giữ nguyên.

### 2.4 `device-capabilities`: mở danh sách chất lượng

`quality / streaming_quality` = `LOW / NORMAL / HIGH / AUTO` → `VERY_HIGH`,
`bitrate / max_bitrate 160 → 320000`. Chỉ đổi trong endpoint capabilities, không đụng file nhạc.

### 2.5 Cờ Jam — nút **Phối nhạc** (`patchJam`)

`/social-connect/v2/devices/<id>/jam_status` và `connect-group`:
bool `false` ở field 1/2 (is_host / can_host / jam_enabled) → `true`; field khác và số khác giữ nguyên.
Tắt: `$argument {"jam_unlock":false}`.

Ghi thật: nếu feed của tab Tạo (casita) không trả mục Blend thì proxy không chèn mục mới vào được —
lúc đó module chỉ mở được cờ, không tự sinh nút.

### 2.6 Badge ở hồ sơ + trang quản lý gói

Mặc định v2.5 = **nền xanh `#1ED760` + chữ đen `#121212` + chữ "ToCam"**, đúng ảnh 3.

```
$argument {"badge_text":"ToCam","badge_color":"#1ED760","badge_text_color":"#121212"}
```

Nhận 4 dạng màu và giữ đúng tiền tố gốc: `#RRGGBB`, `RRGGBB`, `rgb(r,g,b)`, `0xRRGGBB`.
Key được đổi: `badge / pill / chip / tag` khi giá trị là `Premium|Free` → `ToCam`;
`title / name / text / label` chỉ khi đúng bằng `Premium` (nên "Spotify Free" thành
"Spotify Premium", không bị thành "ToCam").

## 3. Thứ tự cài (sai là module chạy 0 lần)

1. Clone repo, chép đè file trong zip, **giữ `.git` và `.github`**.
2. `bash tools/set-repo.sh <user> <repo> main`
3. `bash tools/test.sh` → phải **90/90**
4. `git add -A && git commit && git push`
5. Shadowrocket → **gỡ module cũ** → dán lại `.../main/spotify-vn-premium.module` → dấu `+`
6. Spotify → Cài đặt → **Đăng xuất → Đăng nhập lại** (badge nằm trong cache keychain)
7. Vẫn chưa đổi → gỡ app cài lại

## 4. Kiểm tra đã ăn chưa

- Trang **Chất lượng nội dung**: dòng "Rất cao" phải chọn được.
- Bật `spotify-vn-capture.module` (thay module chính), mở lại trang Chất lượng, xem banner:
  - có `net-fortune … 320` → đã ăn;
  - có `FREE·` → payload còn `free`, gửi mấy dòng `[spot-vn]` đó lại.

## 5. Không hứa

- **320 kbps thật**: server cấp file theo tier + license. Proxy chỉ ép được cấp trong URL và
  danh sách file; nếu server không có bản cấp 2 cho bài đó thì bài nhảy / "Không thể phát" →
  đặt `audio_level=1`.
- **Tải offline**: license + file do server cấp, client không với tới.
- **Nút Phối nhạc**: nếu feed không trả mục, không chèn được.
- **Chữ/màu vẽ cứng trong UI** (không lấy từ payload): HTTP module bất lực, phải jailbreak + tweak.
