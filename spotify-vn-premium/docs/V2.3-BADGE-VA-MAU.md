# v2.3 — Đổi viên badge thành "ToCam" + cam vàng, mở khoá chip chất lượng

## 1. Trạng thái sau v2.2 (theo ảnh + log bạn gửi)

Đã ăn (không phải việc của module này nhưng xác nhận môi trường MITM đúng):

- ads biến mất
- tua được, skip không giới hạn, on-demand chạy
- hàng "Gói Premium của bạn" đã thành Premium (ảnh 3)

Chưa ăn:

- trang Chất lượng vẫn khoá "Rất cao" (ảnh 1–2)
- viên badge vẫn là chữ `Premium` màu xanh Spotify
- nút **Phối nhạc** (Blend) vẫn không hiện

## 2. Vì sao v2.2 không đổi được chữ / màu

`/pam-view-service/v1/GetPremiumPlanRow?locale=vi` trả **JSON REST**, không phải gRPC.
v2.2 chỉ đổi *giá trị* `free → premium` trong payload. Chữ và màu của viên badge vẫn là
thứ server gửi về (`"text":"Premium"`, `"color":"#1ED760"`) → app vẽ đúng như server nói.

Sửa được, nhưng phải sửa **giá trị chuỗi**, không phải sửa trạng thái gói.

## 3. v2.3 làm gì

### 3.1 Nhãn + màu (JSON của `GetPremiumPlanRow`, và cả JSON PAM khác)

| Loại key | Điều kiện | Kết quả |
|---|---|---|
| `badge / badge_text / badge_label / badge_title / badge_name / pill / pill_text / chip / chip_text / tag` | giá trị `Premium` hoặc `Free` | `ToCam` |
| `title / name / text / label / value / plan_name / display_name / short_name` | giá trị **đúng bằng** `Premium` | `ToCam` |
| `color / tint / background / bg / fill` | giá trị là mã xanh Spotify | `#FFA500` |
| bất kỳ chuỗi nào | chứa `#1ED760 #1DB954 #1FDF64 #1AA34A #158A3F #2EBD59 #30D158 #1ED75F` | `#FFA500` (giữ dấu `#` nếu gốc có) |

Chỗ cố ý **không** đụng: `"Spotify Free"` vẫn thành `"Spotify Premium"` như v2.2 (không bị
đổi thành ToCam), vì key `name` chỉ bị đổi khi giá trị đúng bằng `Premium`.

### 3.2 gRPC PAM

Chuỗi đúng bằng `Premium` → `ToCam`; mã màu xanh → cam. Đây là đường dự phòng khi client gọi
`GetYourPremiumBadge` / `GetPlanOverview` thay vì endpoint REST.

### 3.3 Trang Chất lượng

`playback-settings` (`GetAllStoredContentValues` / `GetDeviceSettings`) trả về cặp
`{1: tên_khoá, 2: bool}`. v2.3 thêm `unlockPairs()`:

- tên khoá khớp `premium|lock|restrict|requires|paid|subscriber|upsell|entitle|blocked|disabled|unavailable`
- đang `true` → `false`
- nếu giá trị là message con chứa bool → gạt luôn các bool đó
- key khác (`crossfade_seconds`, `automix_…`) **không** bị đụng

### 3.4 clientrestrictions

- có danh sách cờ → gạt từng cờ `true → false`, giữ nguyên phần còn lại
- JSON → `restrictedIntegrations: []`
- chỉ khi body rỗng hoàn toàn mới trả message rỗng (như v2.2)

### 3.5 Cấu hình nhanh

Muốn chữ / màu khác, thêm `$argument` cho script (Shadowrocket):

```json
{"badge_text":"ToCam","badge_color":"#FFA500"}
```

Sau đó **bắt buộc**:

## 5. Nếu vẫn chưa thấy "ToCam" — đừng đoán, gửi log

Cài `spotify-vn-premium-DEBUG.module`, mở trang **Tài khoản** và trang **Chất lượng** một lần,
vào Tài khoản → lọc `spot-vn-dbg` → gửi 5–10 dòng có `HAS_FREE` / `s=` (v1.3 in cả chuỗi ASCII
bên trong payload). Có chuỗi là chốt được key thật trong một lần.

Trường hợp phải nói thẳng: nếu app **vẽ cứng** chữ/màu trong UI (không lấy từ payload nào),
HTTP module không đổi được — lúc đó cần jailbreak + tweak (đổi `UILabel` text + `UIColor`,
hoặc hook `NSBundle localizedStringForKey:`), xem mục 6.

## 6. Đường khác khi payload không chứa chữ/màu

- **Tweak `.deb` (Dopamine / palera1n, iOS 15–16.6.1)**: hook UILabel/UIControl trong view
  "Gói Premium của bạn", đổi `text = "ToCam"`, `textColor = UIColor(0xFFA500)`.
  Hoặc swizzle `NSBundle localizedStringForKey:` map `"Premium" → "ToCam"`.
- **Frida** (máy jailbreak): script quét view hierarchy, đổi mọi label có text `Premium`.
  Không cần biết internal của Spotify nhưng phải chạy lại mỗi lần mở app.

Cả hai chỉ đổi phần **hiển thị**. Không cái nào mở được tải offline / 320 kbps.

## 7. Cái v2.3 không hứa

- Tải offline và 320 kbps thật: server cấp theo tier (`storage-resolve … ?product=0`), client không với tới.
  Chip chất lượng có thể hết bị khoá nhưng chất lượng thật vẫn do server quyết.
- Nút Phối nhạc: v2.3 mở khoá danh sách restriction và gạt cờ khoá; nếu app vẫn ẩn nút thì
  điều kiện hiện nút nằm ở chỗ khác (capability/plan payload) → cần log DEBUG của lần mở
  tab Tìm kiếm / Tạo để chốt đúng endpoint.
